# 会话与上下文

问答统一使用服务端会话。旧请求字段 `history` 已删除，传入返回 422。
以下接口均使用原有 Bearer 登录凭证；会话归属于 JWT 的 `sub`。

## 请求

首次 `POST /qa/query`（流式为 `/qa/query/stream`）：

```json
{"question":"项目支持哪些检索方式？","request_id":"client-generated-unique-id"}
```

响应 `data` 带 `session_id`、`request_id`、`session_version`。继续对话时带回 `session_id`，每个新问题使用新的 `request_id`：

```json
{
  "session_id":"上次返回的会话 ID",
  "request_id":"another-unique-id",
  "question":"将刚才的回答翻译成英文",
  "qa_config":{"answer_mode":"conversation"}
}
```

- `knowledge` 默认检索知识库，新事实只能引用当前证据；无命中返回 `no_evidence`。
- `conversation` 直接翻译、总结已有对话，不检索，知识库引用为空；无历史时说明缺少内容。
- `POST /qa/sessions` 可预先创建空会话；`GET /qa/sessions/{session_id}` 读取存档、摘要及版本。
- 同一用户以相同 `request_id` 重试同一请求会复用结果，首次未带会话 ID 也可重试。相同 ID 不同内容、重复执行中或并发版本冲突返回 409；冲突后重新读取会话再重试。
- 未知会话 404，尚未清理的过期会话 410，他人会话 403。流开始后的失败通过 `error` 事件返回同名业务错误码。
- SSE 正常事件为 `answer`、`citation`、`done`；无证据/幂等命中可直接 `done`。只有 `done` 表示已保存最终结果；半途断开时重用原请求 ID 查询结果。
- 达到输出限额的结果标记 `incomplete`，可供展示但不进入完整历史；评测记录为 `error`。

## 预算与持久化

默认总窗口 256,000、输出额度 32,000（包括 thinking）、安全余量 8,000 token，因此完整输入达到 **216,000** 时触发压缩；供应商独立输入上限可进一步收紧。按系统、原问题、辅助检索问句、证据、摘要、完整历史与消息封装合计计数，不使用存档总长度或“最大输出两倍”。

正常情况下历史使用剩余预算；15,000 token 只是压缩时保留近期完整轮次的目标。当前证据总预算 16,000，摘要正文目标 4,000、输出上限 8,000；摘要输入按 64,000 分段，每请求最多 4 次。改写使用独立历史视图和 2,048 输出额度。

摘要立即替换工作历史的已覆盖部分并保存；后续回答失败不会回滚摘要。原文留在存档用于展示，不会重新注入生成、改写或摘要。失败摘要不保存，对相同覆盖范围与预算不重复压缩；必要时仅从本次发送视图淘汰最老完整轮。最新完整轮仍放不下则明确报预算不足。

同步与流式使用同一份经过预算检查的消息，完整回答在短事务中按版本提交，模型调用不持有数据库写锁。推理字段不保存为正文，旧回答的已确认引用编号不会指向当前证据。

数据在 `data_dir/sessions.sqlite3`。默认 30 天有效期、2,000 轮、4,000 请求/会话、单会话状态和幂等结果共 16 MiB、10,000 会话、主数据库 256 MiB；事务日志可能短期额外占空间。写入时清理过期数据，空闲时不启动后台任务。容量到顶返回 413，不自动删未过期会话。请求崩溃后 15 分钟可接管重试，旧执行者不能提交。

参数统一见 [defaults.yaml](../config/defaults.yaml)，私有 `local.yaml` 仍优先。默认模型为 GLM-5.3，启用 thinking/low；更换供应商需确认窗口、输出额度及协议。token 使用工程估算，尚需真实 usage 校准余量。

`trace.qa_budget` 记录最终输入计数；`trace.compaction` 记录压缩前后计数、覆盖位置、失败降级和摘要 usage；回答结束原因在 `trace.finish_reason`，真实 usage 在 `trace.usage`。单轮评测每题创建空会话，走相同流程；历史基线不会自动重写。
