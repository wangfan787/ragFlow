## 五分钟复习

主线：**保留文档信息 → 用子块定位 → 父块补上下文 → 窗口控制证据 → 回答附来源。**

- 信息完整性：原文事实是否被保留为可检索内容；图片要真正读内容。
- 证据密度：交给模型的证据中有多少与问题相关。小块、top-k 和引用都不自动保证密度。
- 父子结构：小块减少主题混杂，父块补充解释；窗口过大有噪声，过小可能漏事实。
- 架构：工程职责分层、处理流程分阶段、数据有父子粒度。这不是微服务，也不等于 RAPTOR。
- 上游：RAGFlow 也有模块划分，只按需借鉴图片描述、结构处理和父块恢复；讲场景取舍，不讲“只有我分层”。
- 验证：召回看 Recall/MRR；证据看实际 tokens、必要事实和无关内容；已有代码与新实现的效果分别记录。
