# 指标与参数速查表

更新日期：2026-09-19。用途：忘了某个参数/指标是什么意思、默认值多少、锁定了哪个、成绩多少，翻这一份。详细试错过程见 [`调参实录.md`](调参实录.md)，执行契约见 [`评测计划.md`](评测计划.md)。

## 1. 检索漏斗参数（RetrievalConfig）

数据流：问题 → 每通道捞 candidate_top_k 个 → 加权融合 → 阈值过滤 → 可选重排 → 交出 top_k 条。

| 参数 | 默认值 | 锁定值 | 含义 | 调大/调小的效果 |
|---|---|---|---|---|
| `retrieval_mode` | hybrid | hybrid | 通道门控：vector 只走向量 / keyword 只走 BM25 / hybrid 两路都走。严格消融靠它，不是把权重设 0 | — |
| `candidate_top_k` | 30 | **10** | 每条通道捞多少候选（海选池大小） | 调大→召回池深但易混入噪声（本次污染来源） |
| `top_k` | 5 | **10** | 最终返回条数（QA 时 = 最多几块证据候选） | 调大→召回涨、精度可能摊薄 |
| `similarity_threshold` | 0.1 | **0.2** | 融合分及格线，低于直接淘汰 | 调大→噪声少但可能误杀低分正例 |
| `vector_weight` / `keyword_weight` | 0.75 / 0.25 | 0.75 / 0.25（未动） | 融合分 = 向量分×权重 + 关键词分×权重（各通道 0~1 归一） | 本次扫 6 档是平台 → 瓶颈不在此 |
| `rerank_enabled` | false | false（决策关闭） | 是否做精细二次排序 | recall +5.6pp 但 MRR -3.6pp，QA 重头部 → 按事前规则放弃 |
| `rerank_backend` | rule | — | rule（免费规则）/ cross-encoder（模型，中文需显式配模型） | — |
| `rerank_top_n` | None（=整个池） | — | 送多少候选去重排，约束 top_k ≤ rerank_top_n ≤ candidate_top_k | — |
| `filters` | None | — | 元数据过滤（如按 doc_id） | — |

## 2. QA 证据参数（QAConfig，请求级）

| 参数 | 默认值 | 锁定值 | 含义 |
|---|---|---|---|
| `evidence_mode` | window | **full_parent** | 喂给回答模型的证据切法：child_only 只给命中小碎块 / window 以命中点为中心扩窗口 / full_parent 整块父块 |
| `evidence_window_tokens` | 384 | — | window 模式的窗口大小（本次扫 256/384/512，full_parent 胜出） |
| `context_top_k` | 5 | — | 最多几块证据进提示词 |
| 总预算 | 32768 | — | MVP_QA_LLM_CONTEXT_TOKENS − 输出预留 1024 − 安全余量 256 = 证据可用 token |

## 3. 分块与嵌入参数

| 参数 | 值 | 含义 |
|---|---|---|
| parent_target / max tokens | 512 / 768 | 父块目标/硬上限 token |
| child_target / max tokens | 128 / 192 | 子块目标/硬上限（检索命中的最小单位） |
| embedding_input_budget | 192 | 子块嵌入输入上限，超了报错 |
| 原子块 | code / table / image | 不与相邻块合并；image 一图一块，超长只切描述文字不切像素 |
| profile | parent-child-v2 + sha256 前 12 位 | 进入 chunk_id，参数变了 ID 就变，防新旧混检 |
| Embedding | embedding-3，1024 维，只嵌子块正文（profile: child-body-v1） | 父块只存上下文不带向量 |
| 索引 | ES；生产 `rag-mvp-chunks`，评测 `rag-eval-crud_rag_mini_v1`（9,430 条/1,000 篇） | 向量持久化，调参不用重嵌语料 |

## 4. 评测数据集（crud_rag_mini_v1，冻结）

| 项 | 值 |
|---|---|
| 语料 | 1,000 篇新闻 = 300 正例 + 150 相似困难干扰 + 550 随机干扰 |
| 问题 | 150 条 = 1doc/2docs/3docs 各 50；Dev 30（调参）/ Test 120（只验货） |

## 5. 指标含义速查（见到指标 → 它回答什么问题）

| 指标 | 回答什么问题 | 及格直觉 |
|---|---|---|
| Hit@K | 前 K 里至少命中一个正例吗 | 看下限 |
| Recall@K | 该找到的文档，找到几成 | 检索侧主指标，调参第一标准 |
| MRR@10 | 第一个正确结果排多靠前（第 1 名=1，第 2 名=0.5…） | QA 场景比 recall 更值钱：只有头部进提示词 |
| nDCG@10 | 整体排序质量（多个正例的顺序合不合理） | 综合参考 |
| Evidence Recall | 回答所需的关键事实进了证据没有 | 被检索 recall 封顶（本次两者同为 0.867/天花板现象） |
| Citation Validity | 标注的引用确实来自给出的证据吗 | 生成侧诚实度；child_only 0.77 vs full_parent 0.93 |
| Citation Document Precision | 引用的文档是正例吗 | 引用准不准 |
| P50/P95 延迟 | 一半/95% 请求多快 | P95 看长尾 |
| usage（input/output tokens） | 真实消耗，算成本用 | 不可得记 unavailable，不补零 |
| source_span accuracy | 来源坐标精度：exact 可逐字高亮 / line_only 只到行 / unavailable 不画假高亮 | 诚实分级，不冒充 exact |

## 6. 真实成绩单（2026-09-19 首次真实 run）

**检索（Test 120 题，只验货一次）**

| 变体 | Recall@10 | MRR@10 | nDCG@10 |
|---|---:|---:|---:|
| vector 纯向量 | 0.9236 | **0.9040** | 0.8725 |
| keyword 纯 BM25 | 0.8819 | 0.8153 | 0.8026 |
| hybrid 默认参数 | 0.8819 | 0.8432 | 0.8203 |
| hybrid_rerank | 0.9569 | 0.8953 | 0.8911 |
| **locked 锁定配置** | **0.9750** | 0.8913 | 0.8895 |

（Dev 30 题基线时 hybrid 默认 0.8667 被 vector 0.9556 压制 → 定位为 BM25 归一化加分污染 → 调参后反超。）

**证据模式（Dev 30 题 × 5 配置，deepseek-flash 生成）**：evidence_recall 全部 0.8667（检索天花板）；citation_validity：child_only 0.767 / window256 0.900 / **full_parent 0.933**（锁定）。P95 全部 1.9~2.3s。

**成本**：全量索引 + 全部评测 ≈ ¥2（索引走 GLM embedding-3；生成走 DeepSeek，Dev 实测 150 次调用 22.9 万输入 + 1.8 万输出 token ≈ ¥0.6）。
